  • Stay for Dinner - CSS Art

    Role: Frontend Engineer
    Live Project: stay-for-dinner-three.vercel.app
    Code Repository: github.com/natashapl/stay-for-dinner

    Stay for Dinner is an interactive CSS art illustration built for the DEV Frontend Challenge: Comfort Food Edition. It depicts a cozy kitchen at dusk centered on a pasta and meatball dinner, and every visual element in the scene - the sage cabinetry, the subway tile, the sunset landscape through the window, the food itself - is drawn with HTML elements and CSS. There is no SVG, canvas, image assets, icon fonts, and emoji anywhere in the artwork.

    The scene is explorable rather than static. Visitors can open a recipe drawer from either bowl, plate the dinner step by step, transition the room from dusk to night, run the faucet, and open the refrigerator and wall cabinets to reveal fully drawn interiors. Every interaction works with a mouse, a keyboard, and a screen reader.

    My Contributions

    CSS Illustration

    • Illustrated an entire kitchen scene - architecture, appliances, decor, plants, landscape, and food - using only gradients, border-radius, clip-path, box shadows, and pseudo-elements across roughly 450 DOM elements.
    • Built repeating organic detail such as the distant treeline and the pasta nest as stacks of hard-stop radial gradients on a single element rather than as dozens of nodes, keeping the DOM small enough to score well on performance.
    • Applied a consistent three-face rule to every solid object - lightest top, base-colour front, darker side, with the visible flank always turned toward the centre of the frame - so appliances read as volumes instead of rectangles.

    Scene Architecture

    • Established a single proportional unit, --u: 1cqw, using a CSS size container, then sized every object in multiples of it and positioned everything in percentages. The illustration rescales as one composition at any screen size with no breakpoint moving a single object.
    • Declared the entire depth order in one z-index block rather than scattering local values, and split the shadow pass by depth so back-wall occlusion paints behind the foreground instead of across it.
    • Organised two dozen components and seventeen stylesheets with a deliberate cascade order: design tokens first, artwork back to front, lighting passes next because they re-light everything above them, then interactions, then responsive overrides last.

    Lighting and Depth

    • Lit the whole room in two passes composited over the finished artwork - a mix-blend-mode: multiply shadow layer and a screen light layer - so every surface darkens and brightens through its own hue instead of drifting toward grey.
    • Built a volumetric sunbeam from a blurred, clipped gradient that widens and dissolves along its length, connecting the window to the food and establishing the focal point of the composition.
    • Added an open-refrigerator light that spills into the room, which required moving the effect out of the appliance and into the room's lighting pass, since a stacking context isolates blend modes from everything behind it.

    Interactive Experience

    • Built a recipe drawer as a native <dialog> styled to slide in from the right, inheriting Escape handling and focus containment from the platform and adding backdrop dismissal and focus restoration in JavaScript.
    • Implemented a multi-step plating sequence with enforced order - plate, then pasta, then meatballs - where the food bowls change behaviour based on state, opening the recipe when idle and serving when plating is active.
    • Built a dusk-to-night transition that repaints the sky, landscape, cabinetry, room lighting, stars, and window reflection, with the moon rising behind the hills after the sun sets.
    • Added independent refrigerator and freezer compartments with fully drawn interiors, two opening wall cabinets, and a working faucet with an animated water stream and basin ripple.

    State and Component Design

    • Kept state flowing one way: a single component owns all interaction state and passes it down, and the scene root converts that state into class flags on one element so CSS cascades it to the entire illustration from a single place.
    • Registered the scene palette with @property as typed <color> and <number> values so night interpolates through every intermediate shade rather than snapping between palettes, and so other effects can multiply by the lighting strength directly.
    • Held JavaScript to interaction state and accessibility only - no library beyond React, and no scripted animation anywhere in the artwork.

    Accessibility and Quality

    • Achieved Lighthouse scores of 100 for Performance, Accessibility, Best Practices, and SEO on the production deployment.
    • Overlaid a transparent semantic button on each interactive object rather than wrapping the artwork, since buttons may only contain phrasing content, then drove the same visual response from both hover and :focus-within.
    • Applied aria-pressed, aria-expanded, and aria-controls to scene toggles, announced plating progress through an aria-live region, hid decorative lettering from the accessibility tree, and reduced all decorative motion under prefers-reduced-motion.
    • Measured tab order, focus indicators, and touch target sizes in a headless browser rather than by eye, which surfaced two defects inspection had missed: a scrollable recipe body with no focusable element inside it, unreachable by keyboard, and primary controls rendering as small as 27px tall on a 360px viewport.
    • Corrected page text failing WCAG AA contrast against the background gradient, and fixed touch targets in pixels rather than scene units, on the reasoning that a target is a physical measurement of a fingertip rather than part of the drawing.

    Performance

    • Shipped the full illustration in roughly 21 KB of gzipped CSS, with a largest contentful paint of 0.3 seconds, zero total blocking time, and zero cumulative layout shift.
    • Restricted all animation to compositor-friendly properties - transforms, opacity, and filters - and kept continuous ambient motion to six looping animations across the entire scene.
    • Audited the stylesheets for unreachable rules in a final polish pass and removed 289 lines of dead CSS left over from superseded implementations.

    AI Collaboration

    • Built in collaboration with Claude Code and Codex, working through a twelve-phase implementation brief I wrote, reviewing each phase visually against a reference before continuing.
    • Directed all design and architectural decisions, including dropping proposed interactions that did not earn their place and setting the constraint that the artwork remain pure HTML and CSS throughout.
    • Diagnosed illustration bugs through visual review that automated tooling could not catch.

    Stay for Dinner demonstrates depth in CSS itself rather than in framework tooling - compositing, container-relative units, registered custom properties, and blend-mode lighting - applied with the same accessibility and performance rigour I bring to production work. It is proof that an illustration can be a real interface: keyboard operable, screen reader friendly, motion safe, and fast.

  • Personal Finance App - Frontend Mentor Challenge

    Role: Frontend Engineer
    Live Project: personal-finance-natashasworld.vercel.app
    Code Repository: github.com/natashapl/personal-finance

    Personal Finance App is a comprehensive full-stack web application that helps users take control of their money by tracking transactions, managing budgets, and building savings goals. Built as a solution to a Frontend Mentor challenge and completed in less than two days using AI collaboration, this project goes beyond the original requirements by implementing complete user authentication, a REST API backend, persistent cloud database storage, and a full end-to-end test suite.

    The application gives users a real-time financial dashboard with an overview of balances, budgets, and pots, alongside detailed transaction history with search, sort, and filter capabilities. A built-in demo account lets visitors explore all features with realistic pre-loaded data without having to create an account.

    My Contributions

    Full-Stack Application Development

    • Built a complete full-stack application from the ground up using Angular 21 for the frontend and Ruby on Rails 8.1 in API-only mode for the backend.
    • Designed and implemented the PostgreSQL database schema hosted on Supabase, with all data scoped to individual users for complete privacy isolation.
    • Deployed the frontend to Vercel and the Rails API to Render, configuring each service for production with proper environment variables and CORS policies.

    Authentication & User Management

    • Implemented JWT-based authentication with bcrypt password hashing, including login, signup, and a read-only demo account for visitors.
    • Built an Angular HTTP interceptor to automatically attach bearer tokens to all API requests without any component-level token handling.
    • Enforced demo account restrictions server-side with a require_non_demo! guard on all mutation endpoints.

    Modern Angular Architecture

    • Used Angular 21 standalone components exclusively - no NgModules anywhere in the codebase.
    • Managed all application state with Angular Signals (signal(), computed(), effect()), eliminating the need for RxJS-heavy state management.
    • Applied ChangeDetectionStrategy.OnPush throughout and removed Zone.js entirely in favour of zoneless change detection, improving Lighthouse desktop performance to 100 and mobile performance to 94.
    • Implemented lazy-loaded routes for all five feature pages to keep the initial bundle size minimal.

    Feature Pages & UI

    • Built five fully functional pages: Overview (with a custom SVG donut chart), Transactions (with pagination, search, sort, and category filter), Budgets (CRUD with per-category spend tracking), Pots (savings goals with add/withdraw money flows), and Recurring Bills (with paid and due-soon status indicators).
    • Implemented a collapsible navigation sidebar with a mobile bottom nav that adapts across breakpoints.
    • Built a global toast notification system using Angular Signals with auto-dismiss, success and error variants, and screen reader announcements via aria-live.

    Accessibility & Quality

    • Achieved Lighthouse scores of 100 for Accessibility, Best Practices, SEO, and Performance on desktop, and 100/100/100/94 on mobile.
    • Built a custom FocusTrapDirective that locks keyboard focus inside modals, moves focus to the first interactive element on open, and restores it to the trigger element on close.
    • Applied WCAG AA standards throughout: semantic HTML, ARIA roles, colour contrast, aria-busy on loading states, and role="progressbar" on savings bars.

    Testing

    • Wrote a full Playwright E2E test suite covering 25 test cases across auth flows, budgets CRUD, pots CRUD (including add and withdraw money), transactions CRUD, search and filter, and pagination - all passing.
    • Wrote a Vitest unit test suite with 80 passing tests covering utility functions, service state management, and component logic including pagination, form validation, date formatting, and currency formatting.
    • Diagnosed and resolved several tricky Playwright failures including strict mode locator violations, race conditions between Angular's loading cycle and DOM assertions, and simultaneous toast interference with toContainText assertions.

    AI Collaboration

    • Built in collaboration with Claude (Anthropic) using the Claude Code CLI, completing the full project in less than two days - work that would typically require a team up to a week.
    • Used AI to scaffold the Rails API and Angular application structure, implement the accessibility layer, and write both the Playwright and Vitest test suites.
    • Directed all architectural and implementation decisions, reviewed all AI output, and handled iterative debugging - particularly for Playwright test failures where providing actual error output and page snapshots dramatically improved diagnosis speed.

    Personal Finance App demonstrates my ability to architect and deliver a complete full-stack application end-to-end - from database design and API development through to accessible UI, automated testing, and production deployment. The combination of Angular 21, Rails 8.1, Supabase, and modern AI-assisted development workflows reflects current professional development practices.
